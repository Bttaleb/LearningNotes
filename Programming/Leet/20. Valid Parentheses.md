## 1️⃣ Define (Understand)

**Problem in my own words:**
Given an input string w, comprised of `[], {}, ()`, find whether the input string is in the language L, where L = { w ∈ Σ* | w is properly balanced and nested }

**Formal statement:**
- Input: string s over Σ = { `(`, `)`, `[`, `]`, `{`, `}` }
- Output: true if s ∈ L, false otherwise
- Kind of problem: decision (is w ∈ L?)

**Rules / properties a correct answer must satisfy:**
1. When a closer appears, there must be at least one unclosed opener
2. When a closer appears, the most recent unclosed opener is of the same type
3. When the string ends, the stack must be empty.

"Correct order" made precise: a closer must match the **most recent** unclosed opener (by position, not just by type). That phrase is what forces LIFO → stack.

**Constraints that matter:**
- n ≤ 10⁴
- Values: only `()[]{}`
- What the constraints change in practice: the stack never needs more than 10⁴ chars. The bound technically makes the input set finite (so a DFA exists), but it would need ~3⁵⁰⁰⁰ states, which is just the stack encoded as states. Structure comes from the n → ∞ question; constraints only size the buffers.

**Examples I traced by hand:**
```
Input: s = "{([])}"
Output: True
Why:
- seen opener '{' -> push
- seen opener '(' -> push
- seen opener '[' -> push
- ']' closer -> pop
- ')' closer -> pop
- '}' closer -> pop

Input: s = "([)]"
Output: False
Why:
- seen opener '(' -> push
- seen opener '[' -> push
- ')' closer mismatch -> Fail

Input: s = "{{{}}"
Output: False
Why:
- seen opener '{' -> push
- seen opener '{' -> push
- seen opener '{' -> push
- '}' closer -> pop
- '}' closer -> pop
- end of input, stack still has '{' -> reject
```

## 2️⃣ Classify

**Core question:** Can this be solved with a fixed amount of memory, no matter how long the input gets?
	"is L regular?" -> No

| Answer      | Consequence                                                                                                         |
| ----------- | ------------------------------------------------------------------------------------------------------------------- |
| Regular     | O(1) extra space works, a stack is considered overkill                                                              |
| Not regular | O(1) memory is impossible, you need something that grows with input; a stack, counter with no upper bound, or array |

As input grows, does the amount I need to remember grow without limit? If yes, the language probably isn't regular

**How I know it's not regular:**
- Myhill–Nerode: `(`, `((`, `(((`, … are pairwise distinguishable (`((` + `))` is valid, `(((` + `))` is not) → infinitely many states needed → no DFA.
- Pumping lemma: pick `(ᵖ)ᵖ`; y lies inside the `(`s, so pumping unbalances it.
- Trap: bounded counting is still regular (count mod 3, depth ≤ 5). Only **unbounded** counting forces you past regular.

**Is it [[context-free-languages|context-free]]?** Yes. It's the Dyck language:
```
S → ε | (S)S | [S]S | {S}S
```

## 3️⃣ Choose the Model
**Model / data structure:** deterministic [[pushdown-automata|PDA]] → a stack

**Why the classification forces this choice:**
[[context-free-languages|Context-free languages]] are exactly what PDAs recognize, and a PDA is a finite-state machine plus a stack. It's **deterministic** (one move per input and top of stack, no guessing), so one left-to-right pass is enough: O(n).

## 4️⃣ Specify the Model (Case Table)

List every situation the machine can be in, then group the ones that behave the same way.

**What the machine sees at each step:** the current input symbol and the top of the stack.
- Input ∈ { opener, closer, end of input }
- Top ∈ { empty, opener of the same type, opener of a different type }
- 3 × 3 = 9 combinations → merged to 6 rows: opener (1, top doesn't matter) + closer (3) + end (2, only empty vs. non-empty matters)

| Input         | State / top              | Action                                  |
| ------------- | ------------------------ | --------------------------------------- |
| read opener o | any top                  | push o, move to next character          |
| read closer c | top = opener of c's type | pop the top, move to the next character |
| read closer c | top = other opener       | reject (mismatch)                       |
| read closer c | stack empty              | reject (no available opener o)          |
| end of input  | stack empty              | accept                                  |
| end of input  | stack non-empty          | reject                                  |

Actions are one of: **push**, **pop and continue**, **reject**, **accept**.

**Lookup table:** `pair[]` maps closer → opener (`[')'] = '('`, …), because the stack holds openers and the lookup happens when a closer arrives. Unset slots are 0, so `pair[c] != 0` means c is a closer. It's part of the PDA's transition function, not a grammar.

		push c onto stack
	else: // c is a closer (check top/stack first)
		if stack empty
			reject
		if top != closer's type
			reject
		pop the top
