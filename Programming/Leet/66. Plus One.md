## 1️⃣ Define (Understand)
<!-- Restate it without copying the prompt. Turn every vague word ("valid", "correct order", "matching") into something a program can check. -->

**Problem in my own words:**
`digits` is an ordered array of integers representing **one** larger integer from most significant to least significant in left-to-right order. Given `digits` return the resulting array *incremented by one*.

**Formal statement:**
- Input: 
	- ordered array `digits` with size `digitsSize` of length *n >= 1*
	- each element `digits[i]` ∈ {0...9}
	- no leading 0's
- Output: `digits` incremented by 1
- Kind of problem: decision (yes/no) | **search (find one)** | optimization (find best) | counting
	- goal is to find and return the single output array that satisfies the rule `output = input + 1`
<!-- For string problems: alphabet Σ = { }, language L = { w ∈ Σ* | ... }, question: is w ∈ L? -->

**Rules / properties a correct answer must satisfy:**
1. ordered array must be incremented by 1
2. output array has length `digitsSize`, **unless every digit is 9**, then it has length `digitsSize + 1` (a carry alone is not enough: `[1,9]` → `[2,0]` carries but stays length 2)
3. every output slot holds a single digit 0–9 (a 9 that receives a carry becomes 0, never 10)

**Constraints that matter:**
- n ≤ 100
- Values: 
	- `digits` contain `digitsSize` elements
	- 
- What the constraints change in practice (buffer sizes, which complexities pass): return array should be able to return 1 index larger

**Examples I traced by hand:**
<!-- Include at least one example per rule above that breaks only that rule -->

Output: {1, 3, 5}
Why: Array represents integer 134, +1 is 135

Input: {9, 9}

<!--

**What the machine sees at each step:** 

The digit at `i` (scanning right to left) and whether a carry is arriving. "Add one" = a carry arriving at the last digit, so `carry` starts `true` and the last digit needs no special case.

| Input                     | State / top       | Action                                                                           |
| ------------------------- | ----------------- | -------------------------------------------------------------------------------- |
| start                     |                   | `carry = true`, `*returnSize = digitsSize`, allocate `digitsSize + 1` slots       |
| digit < 9                 | carry arriving    | `result[i] = digit + 1`, carry leaving = no (`carry = false`)                    |
| digit == 9                | carry arriving    | `result[i] = 0`, carry leaving = yes (`carry` stays true)                        |
| any digit                 | no carry          | `result[i] = digit` (unchanged), carry leaving = no                              |
| loop finished             | carry still true  | every digit was 9: `result[0] = 1`, `result[digitsSize] = 0`, `*returnSize = digitsSize + 1` |
| loop finished             | carry false       | return `result` as is                                                            |

Once the carry stops it never restarts: a 9 only produces a carry when one arrives at it (`[9,1]` → `[9,2]`).

## 6️⃣ Build (Code)
```c
int* plusOne(int* digits, int digitsSize, int* returnSize) {
	int* result = malloc((digitsSize + 1) * sizeof(int))
	*returnSize = digitsSize; //default for ints. < 9
	bool carry = true;
	
	for (int i = digitsSize - 1; i >= 0; i--) {
		if (carry && digits[i] < 9) {
			result[i] = digits[i] + 1;
			carry = false;
		} else if (carry && digits[i] == 9) {
			result[i] = 0;
		} else {
			result[i] = digits[i];
		}
	}
	if (carry) {
		result[0] = 1;
		result[digitsSize] = 0;
		*returnSize = digitsSize + 1 // override if int. > 9
	}
}
```

## 7️⃣ Reflect

### Edge cases
- [ ] Empty input
- [ ] Single element
- [ ] One example per rule from stage 1
- [ ] Max constraints (overflow, recursion depth)

**Bugs I hit:**
- **No output at all:** never set `*returnSize`. A C array doesn't carry its length, so LeetCode printed 0 elements.
- **Garbage value printed (`-1094795586`):** wrote every digit to `result[i+1]` but printed from slot 0, so `result[0]` was an uninitialized `malloc` slot.
- **`carry` set but never read:** the flag was assigned and nothing branched on it, so `[1,9]` could not work.
- **`heap-buffer-overflow` (READ):** started the loop at `i = digitsSize`; the last valid index is `digitsSize - 1`.
- **`if` / `if` / `else` in one pass:** the `else` belonged only to the second `if`, so it overwrote the first branch's `digit + 1`. Fix: `if` / `else if` / `else`, one table row per pass.
- **`digits[i] > 9`:** a single digit is never greater than 9; the row is == 9.
- **Checked `digit + 1 > 9` without checking the carry** (first version): a 9 with no carry arriving must stay 9.
- **`[9]` → `[0]`:** the after-loop step for "carry still true" was missing.
