## 1️⃣ Define (Understand)
<!-- Restate it without copying the prompt. Turn every vague word ("valid", "correct order", "matching") into something a program can check. -->

**Problem in my own words:**
A palindrome is a phrase, number, or sequence of characters that reads the same backwards as it does forward. Given an integer x, return true if that integer is a palindrome, and false if it is not

**Formal statement:**
- Input: an integer 'x' that can be of size -2^31 to 2^31
- Output: True or false
- Kind of problem: decision (yes/no) where -2^31 <= x <= 2^31
<!-- For string problems: alphabet Σ = { }, language L = { w ∈ Σ* | ... }, question: is w ∈ L? -->

**Rules / properties a correct answer must satisfy:**
1. legal inputs consist of non-negative numbers
2. legal inputs must read the same backward
3.   

**Constraints that matter:**
- n ≤ 10 digits
- Values: -2^31 to 2^31 - 1 or -2,147,483,647 -> 2,147,483,647
- What the constraints change in practice:  the set of inputs if finite as our `x` can never be larger than 2^31 - 1 which tells us;
	- x is bounded -> set of possible inputs is finite
	- Every finite language is regular -> finite language can always be recognized by a DFA (no pumping required)
	- Regular -> recognizable with [[bounded memory]]: a DFA, or in code, O (1) extra space
- The [[pumping lemma]] proves the unbounded palindrome language `{ W | W = reverse(w) }` is non-regular

**Examples I traced by hand:**

## 3️⃣ Choose the Model
**Model / data structure:** two pointers to store temporary variables

**Why the classification forces this choice:**
- With a "no string conversion" constraint, a string would cause use to occupy O(n) space vs. an integer math approach that occupies O(1)

**Signal(s) in the problem that pointed to it:**
The bound -2^31 to 2^31 - 1 tells use three design choices:
1. use standard 32-bit integer arithmetic
2. reject negative numbers in O(1) time
3. reverse only half the digits to avoid integer overflow

**Naive approach and why it's not enough:**
- Idea: convert the integer to a string and reverse the order, then compare the new order to the original
- Complexity: Time O(n) · Space O(n)
