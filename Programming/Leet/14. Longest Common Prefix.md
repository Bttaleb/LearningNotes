**Problem in my own words:**
A prefix is a letter or a group of letters added to the beginning of a root word. Given an array of strings, return the longest prefix shared amongst the strings

**Formal statement:**
- Input: an array of `n >= 1` strings , each a length `0...m`, over alphabet Σ = {a-z}
- Output: a single string, `""` when nothing is shared
- Kind of problem: decision (yes/no) | search (find one) | **optimization (find best)** | counting
<!-- For string problems: alphabet Σ = { }, language L = { w ∈ Σ* | ... }, question: is w ∈ L? -->

**Rules / properties a correct answer must satisfy:**
1. the answer is a prefix of every string
2. length is capped by shortest string
3. 

**Constraints that matter:**
- n ≤ 200 (most possible elements)
- Values: 
	- `n` (how many strings in the array)
	- `m` (length of the strings, capped by shorted)
	- 
- What the constraints change in practice (buffer sizes, which complexities pass): 
	working in two dimensions (n x m), capped by the shortest string

**What the machine sees at each step:** 

```
eg. ["flo", "flower"]
j = 3 (4th index of each string)
strs[0][j] = "" -> empty
strs[1][j] = "w"
next character is [j+1], previous is [j-1]
if strs[0][j] != strs[1][j] (f✓, l✓, o✓, w✗), return strs[0][0..j-1]
```


| Input                                           | State / top | Action                         |
| ----------------------------------------------- | ----------- | ------------------------------ |
| string `i` has no char at `j` (ran off its end) |             | STOP -> return strs[0][0..j-1] |
| strs[i][j] != strs[0][j]                        |             | STOP -> return strs[0][0..j-1] |
| strs[i][j] == strs[0][j]                        |             | CONTINUE - advance the scan    |
| `j` reaches the end of strs[0] with no failure  |             | return all of strs[0]          |
1. Why do both STOP rows return `strs[0][0..j-1]`?
	Since we failed at position `j`, we know that the characters prior are valid, so we can return them
2. Is the table *exhaustive* AND *mutually exclusive*? At any (i, j) can more than one row fire?
	Mutual Exclusion -> Yes, but only with Row 1 (bounds) tested before Row 2 (compare).
		Ask "has the string ended" before "does the character match"
	Exhaustive -> Yes (by having our fourth outcome)
