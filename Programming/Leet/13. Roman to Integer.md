# Roman to Integer

## 🧩 Problem in My Own Words
Given a string of Roman numeral symbols, return the integer it represents. Usually you just add up the symbol values, **except** when a smaller symbol sits directly in front of a larger one. Then the smaller one is subtracted (IV = 4, IX = 9, CM = 900).

**Constraints that matter:**
- 1 ≤ s.length ≤ 15
- Values: only `I V X L C D M`, and the input is guaranteed to be a valid numeral in [1, 3999]
- Edge cases implied: no need to validate input; subtractive pairs only ever involve I, X, C

**Examples I traced by hand:**
```
Input:  "MCMXCIV"
Output: 1994
Why:    M(+1000) C(-100, since C<M) M(+1000) X(-10, since X<C) C(+100) I(-1, since I<V) V(+5)
        = 1000 - 100 + 1000 - 10 + 100 - 1 + 5 = 1994
```

  - A fixed alphabet with fixed values points to a lookup table

## 🐢 Brute Force
**Idea:** List all 13 tokens (`CM, M, CD, D, XC, C, XL, L, IX, X, IV, V, I`). At each position, try to match a two-character token first, then fall back to one character.

**Complexity:** Time O(n) · Space O(1)

**Why it's not enough:** It actually works fine. It's just more special-casing than you need. The comparison rule below covers all six subtractive pairs without listing them.

---

## 🚀 Optimal Approach
**Key insight (one sentence):**
> A symbol is subtracted exactly when the symbol to its right is bigger, so compare each value with its neighbor and add or subtract.

**Algorithm:**
1. Build a map from symbol to value.
2. For each index `i`, compare `values[s[i]]` with `values[s[i+1]]` (if `i+1` exists).
3. If the current value is smaller, subtract it. Otherwise add it. Return the total.

**Invariant / why it's correct:**
After processing index `i`, `total` equals the value of the prefix `s[0..i]`, where `s[i]` gets its *final* sign. That sign is decided correctly because the only thing that can flip it is `s[i+1]`. Valid numerals never stack subtractions (no "IIX"), so one character of lookahead is always enough.

**Complexity:** Time O(n) · Space O(1)

## 💻 Code
```c
int romanToInt(char* s) {
	static const int table[] = { ['I'] = 1, ['V'] = 5, ['X'] = 10, ['L'] = 50, ['C'] = 100, ['M'] = 1000};
	int total = 0;
	
	for (int i = 0; (char)s[i] != '\0'; i++) {
		int current = table[s[i]];
		int next = table[s[i+1]];
		
		if (current < next) {
			total -= current;
		} else {
			total += current;
		}
	}
	return total;
}
```

**Alternative:** scan right to left and keep `prev`. If `cur < prev`, subtract. This gets rid of the bounds check.

## 🧪 Edge Cases & Bugs
- [x] Empty input (not possible, since length ≥ 1)

- [x] Duplicates: `"III"` → 3, since equal neighbors add
- [x] Negative numbers / zero: not representable
- [x] Max constraints: `"MMMCMXCIX"` = 3999, no overflow concern
