What happens when programs violate language rules and how to identify & avoid such errors
## Uninitialized Variables
A variable that has not been given a known value (through initialization or assignment)
- When a variable *that is not initialized* is given a memory address to use to store data, the default value of that variable is whatever value happens to already be in that memory address

## Nomenclature
- Initialized = The object is given a known value at the point of definition
- Assignment = The object is given a known value beyond the point of definition
- Uninitialized = The object has not been given a known value yet
consider the variable definition
```cpp
int x;
```
Since no initializer is provided, the variable is default-initialized. Thus, we'd say `x` is *uninitialized* since we're focused on the outcome (object not given a known value), not the process

## Undefined Behavior
The result of executing code whose behavior is not well-defined
Implementing undefined behavior may exhibit *any* of the following symptoms
- program produces different result every time it runs
- program consistently produces the same incorrect result
- program behaves inconsistently (sometimes correct, sometimes not)
- program seems like it's working but produces incorrect results later
- program crashes, either immediately or later
- program works on some compilers but not others
- program works  until you change some other seemingly unrelated code

## Implementation-defined behavior
A specific compiler and the associated standard library it comes with are called an **implementation**
Behavior defined by the implementation is called **implementation-defined behavior**.
	I-DB must be documented and consistent for a given implementation
Ex.
```cpp
#include <iostream>
int main() {
	std::cout << sizeof(int) << '\n' // prints how many bytes of memory an int value takes
	return 0;
}
```
Most platforms produce `4`, others may produce `2`s
